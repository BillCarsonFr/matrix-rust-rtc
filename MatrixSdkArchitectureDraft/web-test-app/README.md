# matrix-rtc-web — uniffi npm bindings, acceptance suites, demo

The uniffi-generated npm package for the draft crate, the acceptance test
suites that run through the real wasm bindings, and a demo page. Bindings are
generated by
[uniffi-bindgen-react-native](https://github.com/jhugman/uniffi-bindgen-react-native)
(wasm target), so this is the **same API** Swift/Kotlin get.

```sh
npm install
npm run ubrn:web   # build the crate for wasm32 + generate TS bindings
npm test           # acceptance suites (vitest)
npm run dev        # demo page on vite
```

## Suites (`test/`)

| file | covers |
|---|---|
| `participation.test.ts` | the facade end to end: getters, listeners, join order, `LeftWithKeys`, status |
| `session.test.ts` | slot conditions, sticky expiry on the JS clock, event-type spellings, `computeSessionsFromEvents`, drop guard |
| `ownMembership.test.ts` | compat dialects (2025 sticky, MSC3401 state), heartbeat timers, leave, delegation, `slot_closed`, own connection |
| `encryption.test.ts` | key distribution, inbound verification (cleartext / wrong device), early keys, unencrypted calls |
| `runtimeProbe.test.ts` | runtime assumptions (`tokio::sync::watch`, detached tasks, timers) under wasm |
| `backend.test.ts` | **opt-in** full integration against `../../demo/backend` via the matrix-js-sdk driver (below) |

Two things to know when writing tests: getters are fresh right after an
`emit` (the session is drain-on-read); listener callbacks and inbound *media
keys* are processed by pump tasks — `await tick()` / `waitFor(...)` for those.

## Drivers (`src/`)

- `mockDriver.ts` — `MatrixDriverCallback` in TS modelling a homeserver: records
  outbound calls, **echoes** accepted sticky/state events back into the room
  stream (so our own membership shows up like anybody's), answers `readState`
  from `roomState`, and hosts **simulated peers** (`addPeer` / `peerJoins` /
  `peerLeaves` / `peerSendsKey`) that answer our media key with theirs. Also
  the single source of truth for the fabricated wire shapes (mirrored in
  `src/session/test_support.rs`).
- `jsSdkDriver.ts` — the same seam over matrix-js-sdk v42+: sticky and
  delayed events, room state, to-device (Olm when crypto is on), MSC4195
  token exchange incl. the OpenID hop, transport discovery, and the three
  sinks fed from sync. `createJsSdkBackend()` registers/logs in, syncs and
  creates/joins a room.

## Demo page

Pick a backend (mock, or a real homeserver via matrix-js-sdk), join publishing
or receive-only, and watch tiles (every field the SDK exposes per member),
connections, the key map, the outbound driver log and the debug snapshot. With
the mock: inject peers, let them answer keys ("simulate keys"), close/open the
slot, refuse delayed events.

## Against the demo backend

```sh
make backend-up                          # in the repository root (Synapse + lk-jwt-service + LiveKit)
MATRIX_RTC_BACKEND=1 npx vitest run test/backend.test.ts
# stack on other ports (e.g. a remapped compose override):
#   HOMESERVER_URL=http://localhost:18008 LK_SERVICE_URL=http://localhost:26080
```

Two registered users share a room; A opens the slot, joins publishing, B sees
A's membership with its connection, A holds a real JWT from lk-jwt-service, B
joins, A leaves. The room is unencrypted (no Olm in the node process), so media
keys are not exchanged there — the browser demo with "crypto" does that.

## Layout

| path | what |
|---|---|
| `ubrn.config.yaml` | ubrn config: crate at `..`, features `uniffi` + `runtime-probe` (test-only) |
| `src/generated/` | **generated** TS bindings + wasm-bindgen output (`npm run ubrn:web`) |
| `rust_modules/wasm/` | **generated** wasm shim crate, ignored |
| `Cargo.patch.toml` | merged into the shim's Cargo.toml by ubrn — the wasm-bindgen pin |
| `src/wasmLoader.ts`, `test/wasmInit.ts` | wasm init for vite / node |

## Gotchas

- **Feature resolver v1 in the generated shim**: `rust_modules/wasm` is
  edition 2018, so cargo unifies *target-specific* features into the wasm
  build. Any native-only tokio feature outside `sync, macros, io-util, rt,
  time` fails the wasm build; the crate declares one tokio feature set.
- **wasm-bindgen pin**: ubrn bundles its CLI half at 0.2.100;
  `Cargo.patch.toml` pins the crate side. Bump together with ubrn.
- **uniffi version**: the crate pins `uniffi = "=0.31.2"` to match ubrn 0.31.0-5.
- `Vec<u8>` crosses the FFI as `ArrayBuffer` (`new Uint8Array(key.key)`).
- MSC4143 details the session insists on: member content carries
  `msc4354_sticky_key` (== `member.id`), a slot id is `{application_type}#{id}`.
