# @element-hq/matrix-rtc

MatrixRTC ([MSC4143](https://github.com/matrix-org/matrix-spec-proposals/pull/4143))
participation for web and Node: the [`matrix-rtc`](../README.md) Rust crate
compiled to WebAssembly, with TypeScript bindings generated by
[uniffi-bindgen-react-native](https://github.com/jhugman/uniffi-bindgen-react-native).
The generated API is the same one Swift and Kotlin get, so the crate's docs
and examples apply verbatim.

The host implements one `MatrixDriverCallback` (all Matrix I/O) and consumes
four outputs: memberships, connections, key map, status. No media code is in
here — see [`../MatrixSdkArchitecture.md`](../MatrixSdkArchitecture.md) for the
model and the LiveKit reconciliation loop a host runs on top.

## Install

The package is published to the **GitHub Packages** npm registry, not
npmjs.com. Point the `@element-hq` scope at it once, in the consuming project's
`.npmrc` (or `~/.npmrc`):

```ini
@element-hq:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}
```

GitHub Packages requires a token with `read:packages` even for public packages.
In GitHub Actions the workflow's `GITHUB_TOKEN` works; locally use a classic
personal access token. Then:

```sh
npm install @element-hq/matrix-rtc        # latest tagged release
npm install @element-hq/matrix-rtc@next   # pre-release from the tracked branches
```

Versions track the crate's `Cargo.toml`. `next` pre-releases are
`<version>-next.<run>.<sha>` and sort below the release they precede.

## Use

```ts
import { initAsync, FfiMatrixDriver, FfiParticipationManager, FfiTransportIntent, FfiElementCallCompat } from "@element-hq/matrix-rtc";

await initAsync(); // loads the wasm next to the module; idempotent

const driver = new FfiMatrixDriver(myMatrixDriverCallback); // your MatrixDriverCallback, one per room
const manager = new FfiParticipationManager(roomId, "m.call#ROOM", userId, deviceId, driver, {
  compat: FfiElementCallCompat.Off,
  manageMediaKeys: true,
  requireCrossSignedSender: true,
  useKeyDelayMs: 1000n,
});
manager.setMembershipsListener({ onMembershipsChange: (m) => renderTiles(m) });
manager.setConnectionsListener({ onConnectionsChange: (c) => holdLiveKitRooms(c) });
manager.setKeyMapListener({ onKeyMapChange: (_map, change) => setKey(change) });
manager.setStatusListener({ onStatusChange: (s) => showStatus(s) });

await manager.join(new FfiTransportIntent.ReceiveOnly({ canSubscribe: ["livekit"] }), {
  applicationType: "m.call",
  intent: undefined,
  stickyDurationMs: 3_600_000n,
  keepAliveTimeoutMs: 30_000n,
  degradedLifetimeMs: undefined,
  delegateDelayedLeave: false,
  delegatedDelayMs: 3_600_000n,
});
```

### Loading the wasm

`initAsync()` with no argument resolves `index_bg.wasm` relative to the module
via `new URL(..., import.meta.url)`; Vite, webpack 5 and Rollup rewrite that to
the emitted asset, Node (through the `node` export condition) reads the file
from disk. To control it yourself pass any of `URL | string | Request |
Response | BufferSource | WebAssembly.Module`:

```ts
import wasmUrl from "@element-hq/matrix-rtc/wasm?url"; // Vite
await initAsync(wasmUrl);
```

Serve `.wasm` as `application/wasm` so browsers stream-compile it. No COOP/COEP
headers are needed: the build is single-threaded.

### Subpath exports

| import | what |
|---|---|
| `@element-hq/matrix-rtc` | every generated binding, `initAsync`, `isInitialized`, `defaultWasmUrl` |
| `@element-hq/matrix-rtc/wasm` | the `.wasm` file, for bundler asset handling |
| `@element-hq/matrix-rtc/log-sink` | `installConsoleLogSink(level?)` — the crate is silent until a `LogSink` is set |
| `@element-hq/matrix-rtc/driver/matrix-js-sdk` | `JsSdkMatrixDriver`, a `MatrixDriverCallback` over matrix-js-sdk ≥ 42 (optional peer dependency); `createJsSdkBackend()` for tests and demos |
| `@element-hq/matrix-rtc/testing` | `MockMatrixDriver`: a fake homeserver that echoes accepted events and hosts simulated peers, for your own unit tests |

Everything exported from the root is public API; the `Ffi`-prefixed names are
the generated ones and match the Kotlin/Swift bindings.

## Develop

```sh
npm install
npm run build        # crate -> wasm32 (profile `web`) -> wasm-opt -> tsc -> dist/, then a pack check
npm test             # acceptance suites (vitest) against dist/
npm run build:dev    # + the test-only `runtime-probe` variant into src/generated-dev (runtimeProbe.test.ts)
npm run typecheck    # sources and suites
npm run test:types   # the shipped .d.ts compile with skipLibCheck: false
npm run test:pack    # install the tarball into a scratch Node + Vite consumer (needs network)
npm run dev          # demo page
```

`scripts/build.mjs` is the build; `scripts/check-pins.mjs` runs first and fails
on any drift between the coupled versions (below). Sizes are printed after
each step (wasm ≈ 760 KB, ≈ 290 KB gzipped).

### Suites (`test/`)

| file | covers |
|---|---|
| `participation.test.ts` | the facade end to end: getters, listeners, join order, `LeftWithKeys`, status |
| `session.test.ts` | slot conditions, sticky expiry on the JS clock, event-type spellings, `computeSessionsFromEvents`, drop guard |
| `ownMembership.test.ts` | compat dialects (2025 sticky, MSC3401 state), heartbeat timers, leave, delegation, `slot_closed`, own connection |
| `encryption.test.ts` | key distribution, inbound verification (cleartext / wrong device), early keys, unencrypted calls |
| `runtimeProbe.test.ts` | runtime assumptions (`tokio::sync::watch`, detached tasks, timers) under wasm; skipped unless `build:dev` ran |
| `backend.test.ts` | **opt-in** full integration against `../../demo/backend` via the matrix-js-sdk driver |
| `types/consumer.ts` | the shipped declaration files, from a consumer's point of view |

The suites import the package by name; `vitest.config.ts` aliases that to
`dist/`, so they test what ships, never the TypeScript sources. Getters are
fresh right after an `emit` (the session is drain-on-read); listener callbacks
and inbound media keys are processed by pump tasks — `await tick()` /
`waitFor(...)` for those.

### Against the demo backend

### Layout

| path | what |
|---|---|
| `src/index.ts`, `src/index.node.ts`, `src/init.ts` | the entry points (browser / `node` condition) and the shared loader |
| `src/log-sink.ts`, `src/drivers/matrix-js-sdk.ts`, `src/testing/mock-driver.ts` | the subpath exports |
| `src/wasm-bindgen-types/index.d.ts` | hand-written types for the wasm-bindgen glue (ubrn emits none); copied next to `index.js` by the build |
| `src/generated/`, `src/generated-dev/` | **generated** bindings, published / test-only variant; gitignored |
| `src/app.ts`, `index.html` | the demo page (`npm run dev`), not published |
| `ubrn.config.yaml`, `ubrn.dev.config.yaml` | features `uniffi` / `uniffi` + `runtime-probe` |
| `Cargo.patch.toml` | merged into the generated shim crate: the wasm-bindgen pin and the size-tuned `web` profile |
| `rust_modules/wasm/` | **generated** wasm shim crate, ignored |
| `../rust-toolchain.toml` | stable + `wasm32-unknown-unknown`, so every build is the same build |

### Releasing

CI (`.github/workflows/npm-web-bindings.yml`) builds and tests on every push
and pull request, publishes `next` from `main`, `develop` and
`toger5/architecture`, and publishes `latest` from a `matrix-rtc-v<version>`
tag whose version equals `package.json`'s. To release:

1. bump `version` in `../Cargo.toml`, run `npm run sync-version`;
2. record the binding-surface changes in the repository `CHANGELOG.md`
   (the generated TypeScript *is* the API; the CI summary shows a diff against
   the last published `latest`);
3. tag `matrix-rtc-v<version>` and push.

### Gotchas

- **Coupled versions**: `uniffi` (`../Cargo.toml`) ↔ `uniffi-bindgen-react-native`
  ↔ `@ubjs/core` (both `package.json`) ↔ `wasm-bindgen` (`Cargo.patch.toml`, must
  equal the `wasm-bindgen-cli-support` compiled into ubrn) ↔
  `wasm-bindgen-futures` (`../Cargo.toml`). Bump them together;
  `npm run check-pins` is the gate.
- **Feature resolver v1 in the generated shim**: `rust_modules/wasm` is edition
  2018, so cargo unifies *target-specific* features into the wasm build. Any
  native-only tokio feature outside `sync, macros, io-util, rt, time` fails the
  wasm build; the crate declares one tokio feature set.
- **ubrn's TOML merge cannot change a value's type**, which is why the size
  profile is a custom `[profile.web]` rather than an edit of `release`.
- `Vec<u8>` crosses the FFI as `ArrayBuffer` (`new Uint8Array(key.key)`).
- MSC4143 details the session insists on: member content carries
  `msc4354_sticky_key` (== `member.id`), a slot id is `{application_type}#{id}`.
